# aiq-final — правила роботи

- Це окремий документ рішення для PayPilot/AI Quality Engineering, не eval-kit. Не копіювати сюди код, датасети, reports, traces чи git-історію ДЗ; лише посилання на точні commit/file/run.
- Після кожного курсового завдання виконувати [post-task-checklist.md](post-task-checklist.md), оновлюючи lra.md, evidence-map.md і README.md. Зовнішні результати читати, не змінювати старі ДЗ або їхній index заради синхронізації фіналу.
- Джерело кожного числа/факту — stable E-ID у Evidence Map; розрізняти власний/запасний, вимір/оцінку/припущення, seed/production, прототип/встановлену правку. Для дій потрібен фактичний стан, для причин — вхід кроку й request/span.
- LRA1–5 заповнюються зараз; 6 лише після L13, 7 після L11/L14. Brief/postmortem — після листів і картки L14; answers — після дослівних питань ментора. Не симулювати відсутні результати.
- Документи для CEO/Compliance — українською без неперекладеного інструментального жаргону; технічні ідентифікатори та методику лишати у Evidence Map/джерелах. Бриф до 2 сторінок, postmortem до 1,5, відповіді до 150 слів.
- До здачі brief/postmortem/answers потрібна особиста переробка автора згідно з правилами курсу; не вважати автоматично створений текст його готовою роботою. Робоча LRA — пропозиція для перегляду, не особисте схвалення запуску.
- Перед завершенням звіряти числа, знаменники, scope/конфігурацію, links/anchors, UTF-8, git status/diff і відсутність секретів. Stage explicit task paths. Коміт, push, нові платні прогони та LMS-здача потребують відповідного дозволу користувача; постзадача сама такого дозволу не створює.
