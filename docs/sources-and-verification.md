# Джерела, межі й підготовка до інциденту

## Вхід і версії

11.11.2026 прочитано весь розділ [«Шаблони»](https://www.edu.goit.global/uk/learn/53575439/54507480/55543754/training?blockId=55620604) через відкриту сторінку GoIT: LRA, Board Brief, Incident Postmortem, Evidence Map, answers. Структура перенесена в Markdown зі збереженням запитань, колонок і заголовків; byte-identical експорт не заявляється. Опис, кроки, правила використання ШІ й критерії оцінювання надані користувачем у чаті.

У README зафіксовано дев'ять public джерел. Перед читанням перевірено їхні local HEAD/status та GitHub `main`: SHA збігаються. Поточний L01 stand має окремі локальні зміни, тому їх не цитуємо як публічний результат: контракт беремо з прийнятого ДЗ1, §0–1. У L02 був локальний непублічний звіт та IDE-папка; їх не змінюємо й не використовуємо замість tracked звіту. Номери ДЗ і занять навмисно зіставлені.

Remote-tree перевірка виявила, що raw лабораторної L05, згаданий у старому розборі, не tracked у sourcecommit. Тому в E-07 крок втрати посилається на публічну таблицю з request/span, а raw-посилання веде лише на справді опублікований окремий підсумковий набір із правильно названим scope. Старий репозиторій не виправляли й відсутній файл не переносили. Для первинного повністю публічного трейс-доказу втрати контексту є окремий E-23 з L08.

## Перевірки й відкриті межі

Перевіряємо числа з tracked джерел, denominator і одиниці, різницю між виміром/оцінкою/припущенням, існування віддалених шляхів на exact SHA, локальні посилання, UTF-8, відсутність секретів та копій коду/звітів. Текстова звірка не доводить production-безпеку. Нові model/API-прогони в цій підготовці не потрібні й не виконуються.

Поки немає листів CEO/Compliance, картки фінального інциденту, незалежного фінального CI-гейта після L13 та результатів L11/L14. Їх неможливо чесно замінити старим навчальним експериментом. Власний/запасний означає походження вимірювання; успадкований кейс окремо зазначається, а не ховається.

### Рішення під час підготовки та їхня ціна

1. Виконати детальну інструкцію без додаткового design-погодження, зберігаючи попередню перевагу користувача щодо прямої роботи. Ціна: це робоча пропозиція, зміст і вердикт потребують авторського перегляду перед фіналом.
2. Створити незалежний документний repo, не worktree чи clone старого ДЗ. Ціна: доступність доказів залежить від збереження source-репозиторіїв; full SHA захищає від зміни змісту, не видалення репозиторію.
3. Для prose-only завдання застосувати перевірки структури/посилань/арифметики й незалежний перегляд замість вигаданих software unit tests. Ціна: семантичне тлумачення не доводиться тестом на наявність рядка.
4. Зберегти brief/postmortem/answers порожніми до листів/картки/питань та особистої переробки автора. Ціна: ця публікація — підготовка, не зданий фінальний проєкт.
5. Обмеження public raw L05 явно назвати; не виправляти старе ДЗ й не переносити прихований файл. Ціна: крок втрати L05 перевіряється за опублікованим розбором; незалежний первинний L08 доказ доступний окремо.

### Що незалежний review не засвідчує

- Production-безпека, compliance, встановлені guard-и й частота інцидентів: не заявлені; для запуску потрібні окремі докази. Ціна — no-go не замінює майбутню перевірку впровадження.
- Результати L11–L14, фінальний інцидент, CI red/green та відповіді ментору: лишаються відкритими до появи входів. Ціна — додаткова робота після відповідних тем.
- Відновлення/публікація відсутнього raw L05: поза поточним завданням; обмеження збережене. Ціна — не повний первинний public archive саме цього старого експерименту.
- Byte-identical відповідність GoIT: збережено поля/питання/заголовки після прочитання всієї сторінки, не заявлено побайтовий експорт. Ціна — не зберігається початкове HTML/пробіли.
- Успіх push/видимість repo: не виводяться з review; перевіряються окремою дією. Ціна — локальний commit сам по собі не є публікацією.
- Загальна рівноцінність оцінювачів: не заявлена через development-набір і різні протоколи. Ціна — не можна екстраполювати agreement на всі звернення.

Відкладених Minorнемає. Постзадача збережена в локальному глобальному AGENTS.md за [офіційним механізмом постійних інструкцій](https://learn.chatgpt.com/docs/agent-configuration/agents-md#create-global-guidance); спрацювання в нових задачах потребує читання цих інструкцій, це не фоновий scheduler.
